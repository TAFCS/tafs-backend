\section*{Open Questions and TAFS Decisions at a Glance}

\noindent\fcolorbox{askrule}{askbg}{\parbox{\dimexpr\textwidth-2\fboxsep-2\fboxrule}{%
\textbf{\Large Open questions for UBL} \\[2pt]
\small Please answer these before integration testing. TAFS will adapt to UBL's answers.
\begin{enumerate}[leftmargin=2.2em, itemsep=3pt, topsep=4pt]
  \item \textbf{Are 15-digit 1Bill consumer numbers acceptable?} (10-digit prefix + 5-digit CC.) If 1Bill requires a
        different length, please state it.
  \item \textbf{Shall TAFS give 1Bill a separate endpoint?} TAFS can provide dedicated 1Bill endpoints
        (e.g.\ \texttt{/api/v1/ubl/onebill/bill-inquiry} and \texttt{/bill-payment}) that always add the 1Bill charges, instead
        of relying on \texttt{channel=ONEBILL} in the request. Which does UBL prefer? If the same endpoint is used, can UBL
        always send \texttt{channel=ONEBILL} on 1Bill inquiries?
  \item \textbf{What are the 1Bill charges?} Flat amount or percentage, any slabs or caps, and whether they differ by paying
        bank or wallet. This document assumes PKR 30 until UBL confirms.
  \item \textbf{1Bill settlement.} Please confirm that 1Bill collects its charges from the payer and keeps them, and that only
        the fee amount is settled into the TAFS account.
  \item \textbf{Please issue TAFS's 10-digit 1Bill prefix} (Section~\ref{sec:onebill}) and confirm when it will be live.
  \item \textbf{Payment method tracking.} Can UBL send \texttt{payment\_method} on every payment, for every channel
        (Section~\ref{sec:method})? For 1Bill, can UBL also send the paying bank or wallet?
  \item \textbf{OTC search by CC.} Can the branch teller screen search by CC and show the inquiry result before accepting
        payment?
  \item \textbf{Cheques.} Are cheques posted to TAFS when deposited or only once cleared? If at deposit, how will TAFS be told
        about a returned cheque?
  \item \textbf{Reversals.} This version has no reversal API; errors are corrected by the school on request. Does UBL require an
        online reversal message? If so, please share its format.
  \item \textbf{Daily reconciliation.} Can UBL share a daily settlement statement (transaction id, amount, channel, payment
        method)?
  \item \textbf{Message format.} Does UBL require its own standard message format (field names, fixed-length amounts,
        response codes)? If so, please share the specification.
  \item \textbf{Testing and security.} Please share UBL's outbound IP addresses (for allowlisting), a technical contact, and the
        preferred UAT window. TAFS will provide test students and a UAT base URL.
\end{enumerate}}}


\bigskip
\noindent\colorbox{decbg}{\parbox{\dimexpr\textwidth-2\fboxsep}{%
\textbf{\large TAFS has decided}
\begin{enumerate}[leftmargin=2.2em, itemsep=2pt, topsep=4pt]
  \item \textbf{CC numbers are 5 digits, zero-padded.} No CC is shorter than 4 digits today, and CC 10,000 is close, so TAFS
        writes every CC as 5 digits with a leading zero (e.g.\ \texttt{08088}). This is how it is printed on UBL vouchers.
        Leading zeros are optional when entered (\texttt{08088} = \texttt{8088}).
  \item \textbf{1Bill consumer number = 15 digits:} the 10-digit 1Bill prefix + the 5-digit CC
        (e.g.\ \texttt{1000000000} + \texttt{08088} = \texttt{100000000008088}).
  \item \textbf{Search by CC returns the student's most recent voucher.} If a student has \textbf{two active vouchers},
        the \textbf{most recent one is shown and collected first}. The older one is presented only after the most recent
        one has been paid. TAFS consents to this method (Section~\ref{sec:latest}).
  \item \textbf{The parent bears the 1Bill charges.} They are added on top of the fee shown to the payer; TAFS books
        only the fee amount.
  \item \textbf{Exact amount only, with mandatory channel and payment method} on every payment.
\end{enumerate}}}

\section*{Purpose of This Document}
This document describes the interface TAFS provides to United Bank Limited (UBL) for
collecting school fees through UBL channels. It covers:
\begin{itemize}[nosep]
  \item the collection channels and how a payer identifies a student on each;
  \item the \textbf{Bill Inquiry} (\texttt{GET}) and \textbf{Bill Payment} (\texttt{POST}) APIs, with request
        and response samples for success and failure;
  \item the amount rules: within due date, after due date, and the 1Bill charges, which the payer bears;
  \item mandatory tracking of the \textbf{payment channel} and \textbf{payment method} on every payment;
  \item TAFS's stated consent to resolving every search by CC to the student's most recent voucher;
  \item the open questions TAFS asks UBL to answer, listed first, right after the cover page.
\end{itemize}
Every payload in this document matches what the TAFS implementation sends and accepts.

\section{Identifying a Student}

\subsection{CC number}
Every TAFS student has a \textbf{CC number}, a numeric student code. To stay unambiguous as CCs reach
10,000, TAFS treats every CC as \textbf{5 digits, zero-padded}, and prints it that way on UBL vouchers
(e.g.\ \texttt{08088} for CC 8088). The CC is the identifier for OTC, the UBL app and internet banking.
Leading zeros may be sent or omitted (\texttt{08088} and \texttt{8088} identify the same student).

\subsection{1Bill consumer number}\label{sec:onebill}
For 1Bill, the consumer number is a fixed \textbf{15-digit} number:
\begin{center}
\texttt{[10-digit TAFS 1Bill prefix][CC as 5 digits, zero-padded]}
\end{center}
\noindent Examples, with prefix \texttt{1000000000}:
\begin{itemize}[nosep]
  \item CC \texttt{8088} $\rightarrow$ \texttt{100000000008088}
  \item CC \texttt{10001} $\rightarrow$ \texttt{100000000010001}
\end{itemize}

\medskip
\noindent\fbox{\parbox{\dimexpr\textwidth-2\fboxsep-2\fboxrule}{%
\textbf{Request to UBL: 10-digit 1Bill prefix.} TAFS requests UBL to issue (or arrange through 1Bill) the
\textbf{10-digit 1Bill prefix} for The American Foundation School and share it with TAFS. Until it is received,
TAFS vouchers and this document use the placeholder \texttt{1000000000}. Once UBL shares the prefix, TAFS will
switch to it by configuration; no code change is needed on either side.}}

\subsection{Voucher number}
Vouchers collected through UBL carry a plain serial voucher number (e.g.\ \texttt{12461}), printed small
at the top of the voucher. UBL does \textbf{not} need it to look up a bill. It is returned by the
inquiry for reference, and UBL may echo it in the payment request (Section~\ref{sec:payment}).

% ---------------------------------------------------------------------------
\section{Voucher Resolution: Latest Voucher Rule \& TAFS Consent}\label{sec:latest}

Every inquiry and payment made with a CC or a 1Bill consumer number resolves to
\textbf{the most recent voucher generated by the school for that student}. Concretely, it is the newest
voucher, excluding:
\begin{itemize}[nosep]
  \item vouchers the school has cancelled because a newer voucher replaced them; and
  \item vouchers the school has generated but not yet released to the parent.
\end{itemize}
\textbf{Two active vouchers.} If a student has more than one active (unpaid) voucher, the \textbf{most recent one is
shown and collected first}. The older one is presented only once the most recent one has been paid. In normal use
this is rare: when the school issues a new voucher, it carries the older unpaid amounts as arrears and cancels the
older voucher.

\medskip
\noindent If the student has no active voucher, the API reports the state of the most recent one (already paid, expired
or written off) and collects nothing.

\medskip
\noindent\fbox{\parbox{\dimexpr\textwidth-2\fboxsep-2\fboxrule}{%
\textbf{Statement of consent.} The American Foundation School confirms that it has requested this
method and consents to it: every search by CC number (or by 1Bill consumer number), on every UBL
channel, returns the most recent voucher generated by the school for that student as defined above.
TAFS is satisfied that this is the correct bill to present and collect. TAFS accepts that UBL bears
no responsibility for a payment being applied to that voucher rather than to any earlier voucher of
the same student. Every voucher generated by the school carries the full amount the student
owes, including any arrears.}}

\section{Amount Rules}\label{sec:amounts}

\begin{center}
\begin{tabularx}{\textwidth}{@{}l L@{}}
\toprule
\textbf{Situation} & \textbf{Amount payable} \\
\midrule
On or before the due date & The voucher amount (\texttt{amount\_within\_due\_date}). \\
After the due date (until validity date) & Voucher amount + late payment surcharge, normally \textbf{PKR 1,000} (\texttt{amount\_after\_due\_date}). \\
After the validity date & Not payable. The school must issue a new voucher (response code \texttt{04}). \\
Channel = \texttt{ONEBILL} & The amounts above \textbf{+ the 1Bill charges}, borne by the payer. This document assumes \textbf{PKR 30} until UBL confirms the actual charges (see the open questions at the start). \\
OTC, app, internet banking & The amounts above, with no addition. \\
\bottomrule
\end{tabularx}
\end{center}

\begin{itemize}[nosep]
  \item The inquiry returns \texttt{amount\_payable}, the exact amount to collect \emph{today} on the channel stated in the request.
  \item The payment must carry exactly that amount. Partial payments and overpayments are rejected (code \texttt{06}).
  \item TAFS wants the \textbf{parent to bear the 1Bill charges}: they are added on top of the fee amount shown to the payer.
        On a 1Bill payment TAFS records only the fee amount against the student; the 1Bill charge is noted against the
        payment and never credited to the student's account.
  \item TAFS can change the 1Bill charge by configuration as soon as UBL confirms it; no code change is needed.
  \item Dates are evaluated in Pakistan Standard Time (UTC+05:00).
\end{itemize}

\section{Connectivity \& Authentication}

\subsection{Base URL}
\begin{lstlisting}
https://tafs-backend-production.up.railway.app/api/v1/ubl
\end{lstlisting}
TAFS will also provide a separate test (UAT) base URL with test students before go-live.

\subsection{Authentication}
Every request must carry two HTTP headers. Credentials are issued by TAFS over a secure channel
and are never sent in the URL.
\begin{center}
\begin{tabular}{@{}lll@{}}
\toprule
\textbf{Header} & \textbf{Type} & \textbf{Description} \\
\midrule
\texttt{X-UBL-User} & string & Service user ID issued to UBL \\
\texttt{X-UBL-Password} & string & Password for that service user \\
\texttt{Content-Type} & string & \texttt{application/json} (payment requests) \\
\bottomrule
\end{tabular}
\end{center}
A request with missing or wrong credentials receives response code \texttt{10}. All traffic is
HTTPS (TLS 1.2 or higher). TAFS can additionally restrict access to UBL's outbound IP addresses on request.

\subsection{HTTP status}
A well-formed, authenticated request always receives \textbf{HTTP 200}. The business outcome is in
\texttt{response\_code}. A malformed request receives \textbf{HTTP 400} with a description of the
invalid field, for example a missing \texttt{channel} or a non-numeric \texttt{consumer\_number}.

\subsection{Duplicates, retries and timeouts}
\begin{itemize}[nosep]
  \item Posting is idempotent on \texttt{transaction\_id}. If UBL does not receive a response (timeout), it should
        resend the \textbf{same} request with the \textbf{same} \texttt{transaction\_id}. A payment that was already posted
        returns code \texttt{08} with the original \texttt{tafs\_receipt\_id} and is never booked twice.
  \item Code \texttt{08} therefore means the payment \textbf{is} recorded at TAFS and should be treated as a success.
  \item Code \texttt{99} means nothing was booked; UBL may retry.
\end{itemize}

\section{What Is Printed on the Voucher}
Each voucher issued for collection into the UBL account carries, at the bottom:
\begin{itemize}[nosep]
  \item \textbf{UBL branches:} pay at any UBL branch by quoting the student's CC number.
  \item \textbf{UBL digital app:} go to Bill Payment, select ``TAFS'' as the beneficiary and enter the student's CC number.
  \item \textbf{Other banks / digital channels (1Bill):} pay via ``1Bill Invoices'' using the 1Bill consumer number printed
        on the voucher; 1Bill service charges are added to the bill and paid by the payer.
\end{itemize}
